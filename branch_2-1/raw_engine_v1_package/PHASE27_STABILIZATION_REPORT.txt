2. Runtime watch lifecycle design
- Runtime watch is a sibling lifecycle on top of the existing runtime baseline/current/refresh/rerun-plan flow. Existing runtime freshness/comparability verdicts stay unchanged; phase27 adds separate watch artifacts instead of inserting new tokens into the old manifests.
- New machine-readable artifacts:
  - `runtime_watch_current_phase27.json`
  - `runtime_watch_refresh_phase27.json`
  - `runtime_watch_history_index_v1.json`
  - `runtime_watch_history_index_v1_summary.json`
- Each execution class now carries watch metadata including `watch_status`, `watch_reason`, `sample_count`, `stable_overrun_count`, `clear_count`, `escalation_count`, and `rebaseline_candidate`.
- The watch state machine is fixed as:
  - `CLEAR`
  - `WATCH`
  - `WATCH_STABLE`
  - `WATCH_ESCALATE`
  - `REBASELINE_CANDIDATE`
  - `REBASELINE_REQUIRED`
  - `FAIL`
- Phase27 keeps watch evaluation operator-only. It changes runtime recommendation and combined severity, but it does not alter correctness family status and does not touch `src`.
