2. Runtime Proposal Confidence Gate Design
- Added a machine-readable proposal gate before runtime approval.
- Inputs:
  - runtime current manifest
  - runtime proposal
  - runtime history index
  - runtime watch current manifest
  - runtime watch refresh manifest
  - explicit thresholds for minimum same-fingerprint real samples and minimum watch confidence
- Outputs:
  - proposal_confidence = LOW | MEDIUM | HIGH
  - proposal_gate_verdict = APPROVABLE | NEED_MORE_SAMPLES | REJECT
  - rationale array
  - per execution class evidence:
    - sample_count
    - real_sample_count
    - watch_status
    - watch_confidence
    - trend_direction
    - over_budget_ratio
    - hard_over_budget_count
- Gate policy used in phase31:
  - release_full minimum real samples = 1
  - debug_full minimum real samples = 1
  - asan_full minimum real samples = 5
  - minimum watch confidence = MEDIUM
- Approval is rejected if any relevant execution class shows a hard breach. Approval is downgraded to NEED_MORE_SAMPLES if same-fingerprint real evidence or watch stability is insufficient.
