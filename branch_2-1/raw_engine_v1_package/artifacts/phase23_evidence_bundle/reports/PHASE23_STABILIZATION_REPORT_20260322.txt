2. Runtime Lifecycle Design
- Phase23 lifts runtime into the same lifecycle shape as correctness:
  `runtime current manifest`
  `runtime approved baseline`
  `runtime refresh manifest`
  `runtime rerun plan`
- Runtime entries are now tracked per execution class:
  `release_full`
  `debug_full`
  `asan_full`
  `policy_core`
  `policy_refresh`
  `policy_nightly`
- `tests/tools/runtime_gate_lib.py` owns the machine-readable runtime lifecycle:
  current-manifest generation
  approved-baseline promotion
  refresh against baseline
  rerun-plan generation
  synthetic drift injection
- `tests/tools/run_policy_pipeline.py` now combines correctness lifecycle plus runtime lifecycle into one operator summary with:
  `severity`
  `exit_code`
  `recommended_next_action`
  runtime/current/freshness/comparability/budget rollups
- `tests/runtime_budget_phase23.json` is the operator config for runtime budgets. It keeps strict deltas for full Release/Debug/ASan runs and looser delta thresholds for `policy_core` / `policy_refresh` / `policy_nightly` so tiny operator-stage jitter does not create false stale results.

3. Host / Toolchain Fingerprint And Comparability
- Runtime current/baseline manifests now carry:
  `host_fingerprint`
  `toolchain_fingerprint`
  per-entry `fingerprint_hash`
- Host fingerprint includes:
  OS
  OS release
  CPU/arch
  compiler id/version
  runner tag
- Per-entry comparability additionally distinguishes:
  build type
  sanitizer flags
  execution class
- Comparability rules are now explicit:
  same fingerprint => `COMPARABLE`
  missing provenance => `NOT_COMPARABLE`
  host mismatch => `REBASELINE_REQUIRED`
  toolchain/build/sanitizer mismatch => `NOT_COMPARABLE` or `REBASELINE_REQUIRED` depending on the refresh path
- Cross-host/cross-toolchain runtime mismatch no longer contaminates correctness gate state. It only affects runtime severity and operator action.

12. Remaining Risks
- Runtime baseline is now operational, but the baseline is still single-host and single-toolchain. New runners or compiler changes should trigger `REBASELINE_REQUIRED` instead of being compared directly.
- `policy_core` / `policy_refresh` / `policy_nightly` are intentionally budgeted with relaxed delta thresholds because their wall times are tiny. Operators should still investigate large absolute regressions, but tiny proportional jitter is expected.
- `planner_tie_mixed_organic_compare_ready` remains intentionally diagnostic-only because followup preservation and structure-only enrichment are still zero.
- No semantic mismatch or policy-gate failure exists today; any future mismatch or gate fail still escalates to dump/reduce/regression before planner or primitive semantics can be changed.
