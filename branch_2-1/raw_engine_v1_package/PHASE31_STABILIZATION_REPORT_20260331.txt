2. Runtime Proposal Confidence Gate Design
- Added a machine-readable proposal gate that evaluates whether a runtime rebaseline proposal is safe to approve before any registry switch occurs.
- New gate inputs are the runtime current manifest, rebaseline proposal, runtime history index, runtime watch current/refresh manifests, and explicit policy thresholds for required real sample counts and minimum watch confidence.
- The gate emits:
  - proposal_confidence = LOW | MEDIUM | HIGH
  - proposal_gate_verdict = APPROVABLE | NEED_MORE_SAMPLES | REJECT
  - per_execution_class_evidence with sample_count, real_sample_count, watch_status, watch_confidence, trend_direction, over_budget_ratio, and hard_over_budget_count
  - rationale explaining whether approval is blocked by missing same-fingerprint evidence, insufficient watch stability, hard budget breach, or current/proposal mismatch
- Policy used in phase31:
  - release_full minimum real samples = 1
  - debug_full minimum real samples = 1
  - asan_full minimum real samples = 5
  - minimum watch confidence = MEDIUM
- Hard breach in any relevant execution class rejects approval. Missing evidence downgrades to NEED_MORE_SAMPLES. Stable same-fingerprint evidence with bounded jitter upgrades to APPROVABLE.
